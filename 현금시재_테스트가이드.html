💵 현금시재 기능 테스트 가이드

매출 마감(/closing)의 현금시재 섹션 + 마스터 현금시재 현황 + 불일치 편입 기능을 처음부터 끝까지 확인하는 절차입니다.

사전 준비
  • 배포 후 최신 코드가 반영된 상태여야 합니다 (vercel --prod 완료).
  • 테스트할 날짜를 정합니다 — 해당 날짜에 유비플러스 '현금' 결제 건이 1건 이상 있는 날을 고르세요. (계좌이체만 있는 날은 현금 매출이 0원으로 나옵니다.)
  • 마스터 계정과 지점 계정 둘 다 로그인할 수 있어야 합니다.

0. 용어 정리

용어의미
현금 매출유비플러스 payment_records에서 card_company='현금'인 결제만 집계 (계좌이체·소득공제·지출증빙 제외, 취소 건은 음수로 상계)
기타 입금현금 매출에 포함되지 않는 수기 입금 (예: 현금으로 받은 비카드 매출)
시재 사용금고에서 나간 현금 (예: 거스름돈 충전, 소모품 구입)
예상 현금(정답)현금 매출 + 기타 입금 − 시재 사용 — 이론상 금고에 있어야 할 금액
실제 시재실제로 금고를 세어본 금액 (직접 입력)
오차실제 시재 − 예상 현금. 0이면 일치, ±이면 차이

1. 지점 계정 — 현금시재 입력 및 확인

경로: 지점 계정 로그인 → /closing → 테스트 날짜 선택

페이지에서 영수증 사진 올리기 카드 바로 아래에 "💵 현금시재" 카드가 보여야 합니다.

1-1. 카드 구성 확인

  • 상단 표 첫 행: "현금 매출 (유비플러스 현금 결제)" — 고정 행, 금액이 표시됨 (현금 결제 없으면 0원)
  • 그 아래 "+ 행 추가" 버튼 — 표 위쪽에 있어야 함 (실제 시재 입력칸 위)
  • 행 추가 시 종류 선택: 기타 입금 / 시재 사용, 금액·고객명·비고 입력 (전부 선택 입력)
  • 하단: "실제 현금시재(원)" 입력칸 + [현금시재 확인] 버튼

1-2. 확인 전 상태 확인

1
실제 시재를 아무것도 입력하지 않고 [현금시재 확인]을 눌러보세요.
2
정상: "실제 현금시재를 입력해주세요" 같은 안내 또는 정답/오차가 표시되지 않아야 합니다. (확인 전에는 "확인을 누르면 표시됩니다" 안내만 있어야 함)

1-3. 정상 저장 테스트 (오차 0 만들기)

1
표에서 현금 매출 금액을 확인합니다. 예: 150,000원
2
실제 시재 입력칸에 현금 매출과 동일한 금액을 입력합니다 (기타 입금/사용이 없으면 그대로). 예: 150000
3
[현금시재 확인] 클릭 → 아래 결과가 나타나야 합니다:
  • 예상 현금 = 150,000원 (정답)
  • 실제 − 예상 = 0원 → ✅ 일치 표시
4
페이지를 새로고침(F5) → 입력값이 그대로 복원되는지 확인 (DB 저장 확인)

1-4. 기타 입금/시재 사용 테스트

1
"+ 행 추가" 클릭 → 종류 기타 입금, 금액 10000, 고객명 테스트, 비고 테스트입금 입력
2
"+ 행 추가" 한 번 더 → 종류 시재 사용, 금액 5000 입력
3
[현금시재 확인] 클릭 → 예상 현금이 현금매출 + 10,000 − 5,000으로 바뀌는지 확인
4
새로고침 후 수기 행 2개가 복원되는지 확인

1-5. 오차 테스트

1
실제 시재를 예상 현금과 다른 값으로 바꿉니다. 예: 예상 155,000인데 150000 입력
2
[현금시재 확인] → 오차 −5,000원이 빨간색으로 표시되어야 합니다.
3
다시 맞는 값으로 돌려놓고 확인 → 오차 0 ✅ 복귀 확인

1-6. 불일치 편입 테스트 (핵심)

1
실제 시재를 일부러 틀린 값으로 저장해 둡니다 (오차가 생기게).
2
같은 페이지의 구분별 비교표 맨 아래에 "현금시재(실사)" 행이 생겼는지 확인:
  • 결제내역 칸 = 예상 현금, 영수증 칸 = 실제 시재
  • 차이 칸에 오차 금액이 빨간색으로 표시
3
페이지 상단 써머리 박스에 "⚠️ 불일치 N건" 목록에 현금시재 ±N원 불일치 — 예상/실사 문구가 포함되는지 확인
4
메모 없이 [마감 저장하기] 클릭 → 메모 입력을 요구하는 안내가 뜨고 저장이 차단되는지 확인 (기존 불일치와 동일 규칙)
5
현금시재 행의 메모 칸에 사유 입력 → 메모 저장 → 마감 저장 → 완료 시 불일치 내역에 현금시재 건이 기록되는지 확인
6
오차를 0으로 되돌려 저장하면 비교표에서 현금시재 행이 일치 처리되고 불일치 목록에서 빠지는지 확인

1-7. 잠금 확인

1
마감 저장이 완료된 날짜에서는 현금시재 카드가 수정 불가(잠금) 상태인지 확인 — 저장 후 변경 시도 시 안내가 떠야 합니다.

2. 마스터 계정 — 현금시재 현황 테이블

경로: 마스터 로그인 → /closing → 지점 "전지점" + 테스트 날짜 → 맨 아래로 스크롤

"💵 현금시재 현황" 테이블이 보여야 합니다.

2-1. 전체 지점 표시 확인 (이번 수정 핵심)

  • 테이블 행 = 해당 날짜 결제내역이 있는 모든 지점 + 시재를 저장한 지점 (합집합)
  • 시재를 입력하지 않은 지점도 행이 나와야 합니다 — 실제 시재/오차 칸이 - 표시
  • 컬럼: 지점 / 현금 매출 / 기타 입금·사용 / 예상 현금(정답) / 실제 시재 / 오차 / 링크
  • 미입력 지점 링크는 "입력 →", 입력된 지점은 "수정 →"

2-2. 값 정확성 교차 검증

1
아무 지점의 "수정 →" 클릭 → 지점 뷰의 현금시재 카드로 이동하는지 확인
2
지점 뷰의 예상 현금이 마스터 테이블의 예상 현금(정답)과 동일한지 확인
3
실제 시재를 바꿔 저장 → 마스터 테이블로 돌아와 오차가 즉시 반영되는지 확인 (F5)
4
오차 0인 지점은 오차 칸이 초록 0원, 오차 있는 지점은 빨간 ±금액인지 확인

2-3. 정렬 확인

1
지점명이 가나다/영문 순으로 정렬되어 있는지 확인 (결제내역 지점명 기준)

3. 알림 패널 UI 확인 (매출 마감 상단, 마스터만)

경로: 마스터 → /closing → "📨 마감 알림 설정" 카드

좌측 4개 행(미제출 발송 / 불일치 발송 / 지점 발송 / 테스트 발송)의 레이아웃을 확인합니다.

3-1. 행 정렬 확인

  • 각 행 = 체크박스 + 굵은 라벨(1행) + 회색 설명(아래 행) 구조
  • 4개 행의 체크박스가 같은 높이(위쪽 정렬)에 맞춰져야 함
  • 라벨이 2행으로 잘리지 않아야 함 (nowrap 적용됨)
  • 설명 문구는 길면 아래로 펼쳐지되 잘리거나 가로 스크롤이 생기면 안 됨

3-2. 지점별 알림 그리드 확인

  • 우측 "지점별 알림" 영역에 해당 날짜 결제내역 지점 체크박스들이 카드형으로 나열
  • 지점명이 한 줄로 표시되고 체크박스와 간격이 균일해야 함

4. 예외 케이스

상황기대 결과
현금 결제 0건인 지점현금 매출 0원, 기타 입금만 입력하면 예상=입금합계
기타 행 없이 시재만 입력예상=현금매출, 실제=입력값 → 오차 표시
행 추가 후 전부 삭제기타 입금/사용 0으로 계산, 행은 저장되지 않음
마감 저장된 날짜현금시재 카드 잠금 — 수정 불가 안내
지점 계정으로 타 지점 날짜 조회본인 지점 데이터만 표시 (기존 권한 유지)
결제내역 없는 날짜현금시재 현황 테이블 자체가 안 나옴 (결제내역 없으면 날짜 목록에도 없음)
